# Game Assistant 知识库建设方案（2026-10-10）

## 为什么需要

现有模型只掌握「账号持有的从者 + 他们的技能/宝具」，因此每一次分析都被缺数据卡住：
礼装只知道充能、纹章完全缺失、助战只能靠自己持有、未来活动无法预知。要把 3T 做扎实，
需要的是一套**目录侧知识库**（与账号侧私有数据分离）。

## 数据源验证结果（Atlas Academy，2026-10-10 实测）

| 知识库 | 来源（已验证可用） | 体积 | 关键字段 |
|---|---|---|---|
| 全英灵库（含未持有） | `/export/CN/nice_servant.json`（本地已有 459 条缓存）＋ `/nice/CN/servant/{id}` | ~45MB | 技能/宝具/被动/追加技能、攻击成长、卡组、hit 分布、特性 |
| 概念礼装库 | `/export/CN/nice_equip.json` | 18.58MB | 效果（充能/增伤/掉落加成）、ATK/HP、cost、满破标记 |
| **指令纹章库** | `/export/CN/nice_command_code.json` | **0.50MB** | 纹章效果（如「花之魔术师」+10% 宝具值）、可装备卡色限制 |
| 魔术礼装库 | `/export/CN/nice_mystic_code.json` | **0.18MB** | 三技能效果与逐级数值（含冷却减少，目前只有 21 件手抄快照） |
| 自由关卡/副本信息 | `/export/CN/nice_war.json` | 22.02MB | 关卡、AP、掉落、敌人编成（自由关卡素材刷取用） |
| 未来活动库 | `/export/JP/nice_event.json` ＋ JP `nice_war.json`（**日服领先国服版本**） | 37.88MB+ | 活动时间、加成礼装、Free 本掉落、素材需求 |
| 职阶天赋树 | `/export/CN/nice_class_board.json` | 2.50MB | 节点、消耗、增益（需与账号解锁状态结合） |
| 素材库 | `/export/CN/nice_item.json` | 1.00MB | 素材名称/图标/用途（配合自由关卡做刷取建议） |

单条接口（`/nice/CN/MC/1`、`/nice/CN/CC/1`、`/nice/CN/equip/1`）也可用，但批量导出更省事。

## 存储与刷新设计

- 目录：`AIproduct/game_assistant_kb/`，每个库一个**压缩后**的 JSON（只留分析需要的字段），
  外加 `kb_meta.json` 记录来源 URL、抓取时间、条目数、SHA256。
- 刷新方式沿用现有习惯：每个库一个可重跑脚本（参考 `servant_stats.py` / `skill_effects.py`），
  下载 → 压缩 → 落盘 → 打印统计；配套 pytest 断言条目数量级与关键样例（如「花之魔术师」= +10% 宝具值）。
- 原始大文件（100MB+ 合计）不长期保留，必要时按需重下；缓存到 `D:\workSpace\code\_research\`。

## 与账号侧的分工

- **目录侧（本方案）**：某从者/礼装/纹章「是什么、有什么效果」。
- **账号侧（`game_assistant_private.db` + 手抄快照）**：我「有没有、练到什么程度」
  （技能等级、宝具、追加技能、职阶天赋树解锁、戴冠/圣杯状态、纹章打在谁的第几张卡上）。
- 两者交叉才能得出可执行方案：例如「花之魔术师」的 +10% 是目录事实，
  「打在所长的蓝卡上」是账号事实（现由 `COMMAND_CODE_CHARGE` 配置表承载）。

## 建议实施顺序

**P0（直接服务当前 3T 工作）**
1. **指令纹章库**（0.5MB，最小、收益最直接）：单核暴击场景大量使用（兽爪/暴伤/花之魔术师），
   目前完全缺失；同时把「账号上谁带了什么纹章」补进账号侧配置。
2. **概念礼装库**（18.6MB）：现在只知道「充能礼装 +2000ATK 假设」，
   实际要区分开局充能 / 增伤 / 掉落加成 / 倍卡，并支持「尽量不占掉落位」的排序。
3. **魔术礼装库完整化**（0.18MB）：把 21 件从手抄快照升级为全量目录数据 + 账号等级，冷却减少等已能解析。

**P1**
4. **全英灵库**（含未持有）：支撑「借好友助战」的候选评估（现在只能从自己 261 名里挑）。
5. **自由关卡信息库 + 素材库**：缺素材时给出刷取建议（活动之外的需求）。

**P2**
6. **未来活动库（JP 领先）**：提前知道下个活动的加成礼装/Free 本结构，用于提前规划。
   注意：国服排期不能按日服进度线性推断，只能作为「候选」并标注来源为 JP。
7. **职阶天赋树 + 戴冠/圣杯投入**：需要账号侧解锁状态才能算，属于长期项；
   「戴冠」的具体含义与数据来源需要与用户确认后再设计。

## 开放问题（需用户确认）

- 未来活动库是否现在就要（需要在日服数据与国服排期之间做不确定性标注）。
