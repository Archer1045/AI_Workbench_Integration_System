## Phase 0 - 在家且 90++ 已解锁

- [ ] 确认第十二话和活动前置任务已完成。
- [ ] 确认 90++ 神剑改め 燃えろ翡翠剣 可见，AP40。
- [ ] 确认 MuMu 实例、ADB 端口和 SurfaceFlinger/logical display ID。
- [ ] 确认没有正在运行的其他模拟器/ADB 任务。
- [ ] 记录当前 AP、苹果和令咒数量；不自动消耗苹果/圣晶石/令咒。

## Phase 1 - 真实数据替换

- [ ] 从上到下采集 90++ 三个波次的敌人名称、职阶、数量、HP、特性和效果。
- [ ] 标记 verified=true，移除 mock 标记。
- [ ] 从账号读取本次候选从者的等级、宝具、技能、追加技能。
- [ ] 录入候选礼装、满破状态、礼装等级和 Cost。
- [ ] 录入御主礼装和可用技能等级。
- [ ] 录入助战要求或候选助战。

## Phase 2 - 推荐与门槛

- [ ] 生成至少一个 TeamPlan 候选。
- [ ] 明确每回合技能、宝具、目标和卡片顺序。
- [ ] 所有三回合伤害门槛通过。
- [ ] NP 门槛和回收条件通过。
- [ ] 明确替代方案、最低配置和失败条件。
- [ ] 用户明确确认该 TeamPlan，未确认的候选不能进入执行器。

## Phase 3 - 只读 Dry Run

- [ ] 获取 emulator 和 adb 独占资源。
- [ ] 读取当前界面和活动入口，不点击战斗。
- [ ] 检查编队、概念礼装、御主礼装、支援和 AP。
- [ ] 对比实际队伍与 TeamPlan。
- [ ] 输出 preflight 结果并在任何偏差时停止。

## Phase 4 - 人工监督的首局

- [ ] 只执行第一局，不自动连续刷本。
- [ ] 每回合可暂停、检查状态并继续。
- [ ] 任一状态偏差、未知弹窗、支援异常或伤害显著偏离时立即停止。
- [ ] 首通奖励、任务奖励、商店兑换保持人工。
- [ ] 保存运行日志、截图、回合耗时和结果。

## Phase 5 - 重复执行

- [ ] 首局人工确认通过后，才允许一次重复战斗。
- [ ] 验证重复战斗确认、暂停/恢复和异常停止。
- [ ] 验证资源租约在成功、失败和中断后正确释放。
- [ ] 至少连续 3 次稳定后才考虑受控批量执行。

## Hardware/User Actions Required

以下步骤必须在家里、能看到模拟器时完成：

- 90++ 解锁和真实敌人数据采集。
- 当前账号编队、礼装、御主礼装和助战确认。
- 第一局人工监督。
- 暂停、恢复、异常弹窗和断线处理。
- AP、苹果和令咒的最终人工授权。
